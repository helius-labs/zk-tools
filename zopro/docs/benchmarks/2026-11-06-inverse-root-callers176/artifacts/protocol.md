# Lazy inverse-root codec: complete-caller protocol

This protocol is fixed before the first caller observation. It tests the unchanged qualified binaries from inverse-root-codec176, without rebuilding them: frozen source176, fresh OFF using the new shared field library, and ON selecting the lazy root product. Qualification commit ba46280d269aae0ed59dd1bdabc91bf3b0356719 is already pushed. The current production SDK is unchanged.

The 24 contexts are G1/G2 × 200/201/352/353 points × 1/16/32 workers. Full batches and scalar tails are retained. Each process owns one distinct public-generator fixture per worker, seed19+worker. The existing harness checks final output independently against generator arithmetic after timing, matches output hashes/capacities across all arms, and requires zero timed allocations. These fixtures are not arbitrary full-width curve coordinates. Native field qualification separately covers independent Arkworks full-width/lazy input populations. Complete caller speed alone cannot establish proof speed.

The existing harness uses a benchmark Rayon pool with 512KiB stacks, pinned worker TIDs: CPU2 solo, physical cores0–15 for16, CPUs0–31 for32. Fixtures run through par_iter_mut inside pool.install; a particular fixture is not permanently attached to one worker TID. Timing includes the install/scheduling boundary. Three128-round priming/check passes and a reset precede timing. Generator checks, digesting, allocation assertions, capacities and JSON are outside the clock. The existing global allocation counter sees no allocations in timed calls; it is not an allocator-throughput benchmark. No production pool or buffer is added.

Fixed environment: MALLOC_ARENA_MAX=32, MALLOC_MMAP_THRESHOLD_=1073741824, MALLOC_TRIM_THRESHOLD_=-1. All processes run serially. No builds, packaging, large hashes or other owned CPU workload overlap the capture. Host topology, kernel, tools and governor observations are saved before execution; frequency is not locked by this protocol.

There are72 preflight processes (64 rounds each) and one strict preflight checker. Then15 paired blocks include all24 contexts and three arms: context order rotates by block and reverses on odd blocks; arm order rotates by context+block and reverses on odd blocks. Latency rounds per worker are32768 at200/201 and16384 at352/353, fixed before observing this candidate. There are1080 latency processes. Neither a pilot, an extra block, a reroll nor a favorable subset may replace them.

The rank interval is the fourth through twelfth of15 paired ratios (zero-based3 and11), with median rank7. Every context checks fresh OFF/frozen calibration inside[0.97,1.03], and both ON/OFF and ON/frozen nonregression with interval upper bound≤1.01. Gain checks require upper bound<1 and at least11/15 ratios<1, without a minimum positive gain: separately G1 and G2 equal-log aggregates over all four32-worker sizes, each against both controls, and an equal-log aggregate over all24 contexts against both controls. These are78 timing checks (24 calibration,48 nonregression,6 gain). All are retained and required; a failed gate remains a failed gate. Any improvement is reported numerically even if the gate fails. No new proof goal is defined by this component gate.

Diagnostics follow ALL latency. For each curve, profile200w1,200w32 and352w32 in all three arms:18 grouped perf-stat calls and18 cycles profiles. Solo200 profile rounds2097152;32-worker profile rounds65536; stat uses one quarter of those counts. These counts come from prior control duration/cycle observations, not candidate observations. Fixed cycles:u period16000000, no frequency sampling,512 mmap pages; caller FIFO enable/disable brackets the existing timed region. Counters are cycles, instructions, cache misses and branch misses, each requiring numeric counts and≥90% coverage. They are diagnostic ratios, not a causal cache-level claim.

Each profile requires at least1000 samples,≤5% unknown symbols, zero lost events, exact period, expected PID from actual executable MMAP, owned TIDs from FORK metadata, assigned CPU for every worker sample and legal taskset CPUs for other owned threads. At least95% of samples must be on the measured workers. Small samples on main/constructor owned threads are reported separately. Inadequate profiles are not extended. Raw data ownership/hash is checked before decoding. Each recording is decoded once into samples, once with metadata, once for attributes and once for the loss scan. Full raw and decoded traces stay local with hashes; compact symbols, receipts and source are publishable.
