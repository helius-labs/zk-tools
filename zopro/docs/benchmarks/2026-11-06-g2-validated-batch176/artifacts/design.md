# Validate borrowed G2 destinations once

Hypothesis: remove repeated destination/batch bounds checks from the actual G2 prefix/reverse kernel, without changing field arithmetic or storage. This is a work-removal test, not a prediction of a breakthrough. Accepted full-proof phase evidence still identifies query work as the main target, with its observer limitations retained.

At the safe function boundary, validate every encoded destination after masking its sign bit against the same borrowed mutable bucket slice length. Validation must finish before any bucket or scratch mutation. Use fixed LANES-sized borrowed array chunks for full SIMD batches, preserving original order. Only bucket accesses proved by that validation and prefix-record accesses proved by the completed forward loop become unchecked. Keep original arithmetic, sign handling, tail formulas, inversion, record geometry, capacity policy and exceptions. No new buffer, point representation, hardware gather, key/table/plan, production pool or field operation is introduced.

Safety: Rust slice borrowing fixes bucket length for the call and excludes safe concurrent mutation. Every consumed encoded index is validated against that exact slice. The immutable batch cannot change between validation and use. Copy point values before writes; do not construct multiple mutable point references. Full chunks partition batch[..full] exactly. The forward loop pushes one prefix record per chunk, after clearing/reserving; reverse enumeration visits exactly those same records. Panics unwind before any subsequent unchecked operation. Scalar-tail indices are included in validation; tail storage retains checked access. Uniqueness and nonzero-denominator requirements remain the existing arithmetic preconditions and are not new unsafe-memory assumptions. Invalid indices panic before writes rather than reaching unchecked memory.

Build isolated OFF/ON cores and actual caller executables from all176 accepted-source files. Reuse the exact original accepted native field/support libraries; no new field build or field-suite repetition. Keep the original OFF function body byte-exact behind its cfg. Diagnostic G1/G2 adapters and timing body remain exact, except the driver's compile flag name. ON runs the full changed-core suite including boundary/reuse and invalid-index tests; OFF runs the new shared integration case. Inspect actual optimized G2/G1/inverse functions before any timing. Fewer checks or smaller code are not a performance result. Qualify/publish/commit/push that stage before freezing matched caller latency and automatic profiling.

Prior direct-reference packing, descriptor arrays, direct AoS hardware gather, stored denominators and late-Y variants remain closed. This mechanism adds no descriptor or alternate coordinate loader. The history review found no exact once-at-boundary destination validation implementation; this is not an exhaustive novelty claim. Literature leads Noël–Plantard/Hrabar, quotient-prefix variants, symmetric norms, projective and four-lane paths were found already represented; none is reopened or claimed new. The signed-pair/joint-complex candidates remain closed without a subset rescue.

Passing caller evidence would select all-eight plus merge54 SDK, correctness, portable/resource and independent Gnark qualification before adoption.
