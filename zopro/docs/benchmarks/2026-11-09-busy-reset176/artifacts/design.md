# Borrowed-window busy bitmap completion

Goal remains verified single-proof CPU AVX >=10x supplied M5 CPU ALL8, with CPU and Metal comparisons. This is a distinct bounded metadata change to the dominant streaming consumers, not a claim of a twofold improvement or a reopening of the closed option-owner experiment.

In both accepted borrowed G1 and G2 Windows, a busy bit is set exactly when an ordinary nonempty bucket addition is appended to the current pending batch. Collision arrivals go into the queue without changing busy bits. First writes, equal-X exceptions and projective spill handling do not set busy bits. The batch kernel completes every pending destination before any queued point is drained. Therefore, at execute entry the set of busy bits equals the set of current pending destinations; after the kernel finishes every busy bit may be cleared. This relies on existing Window ownership and unique pending destinations, not on empirical key distributions.

Replace repeated indexed word-zero stores with busy.fill(0) when busy.len() <= batch.len(); otherwise keep the exact original indexed loop. This fixes the policy prospectively by the number of word stores in the two source schedules, with no tuning sweep. One additional branch is charged per nonempty batch. Empty execute remains a no-op. The sparse original route avoids scanning a large table for a short tail.
