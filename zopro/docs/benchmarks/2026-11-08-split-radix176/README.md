# Finite-field split-radix work screen

**Ordinary split-radix removes no scalar field products or additions relative to unit-pruned radix2 in this screen.** Algebra and complete Euler-operator checks pass, but the necessary strict arithmetic-saving gate fails on all nine saved geometries. No native implementation or timing trial is selected. This does not establish identical hardware performance or a lower bound for other transform algorithms. Production remains unchanged.

The familiar complex FFT saving treats multiplication by a fourth root of unity as a free sign/swap. In BN254 Fr that root is a dense field constant and must be charged. The [Johnson–Frigo paper](https://fftw.org/newsplit.pdf), sections I–II, discusses complex flop counts and conjugate-pair split-radix; those counts are not imported here. [FLINT's generic-ring description](https://flintlib.org/doc/algorithms/fft/dft-algorithms.html) supplied an ordinary-split lead. Its current documentation warns parts are generated by an LLM, so the equations/counts are derived and executed independently. No external implementation or reported speedup is copied.

For N≥4, ordinary split-radix computes one even N/2 transform and two odd N/4 transforms. For each k<N/4 it forms t=w^k O1[k], u=w^(3k) O3[k], then E[k]±(t+u) and E[k+N/4]±iota*(t−u). The first two roots are one only at k=0; iota is never ±1. The full field-product recurrence is therefore

```text
radix2: M(N) = 2M(N/2) + N/2 − 1
split:  M(N) = M(N/2) + 2M(N/4) + 3N/4 − 2
both:   M(N) = N*log2(N)/2 − N + 1
both:   A(N) = N*log2(N) add/sub operations
```

Bases are M(1)=M(2)=0, A(1)=0, A(2)=2. Unit-root products are skipped equally in both scalar circuits. Fourth-root products are a subset of M, never a second added count. Exact integer recurrence checks pass through N=2^28. This is an identity for these recipes, not a universal multiplicative-complexity bound.
