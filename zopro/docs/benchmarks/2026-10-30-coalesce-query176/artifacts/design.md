# Native sparse coalescing: complete A/B2 queries

The bounded whole-scalar count screen selected an actual native implementation. It saved 3.329%/3.104% of modeled primary A/B2 generic fill/top pairs after formation. These are not proof-speed estimates. Production remains accepted source176/SDK6d83/ledger27353; no implementation is adopted by this experiment.

The private classifier performs the original sampling, checked reservation, capacity policy, owned-word hash insertion, stable class IDs, zeros and exact population cutoff. A declined full population returns its existing values/classes/counts instead of discarding them. All admitted grouping and unsupported/sampling-declined inputs retain original paths. No second full-scalar hash pass is added. Only the existing native A width12/parts1 and exclusive B2 Phi12/parts2 paths are candidates.

Rejected classes use their existing usize count records for packed original-count/representative/tile-group tags. Eligible queries have fewer than65536 rows on native64-bit hosts, so original counts fit16bits, local group IDs fit16bits and representative+1 fits32bits. The original count stays in the low16bits. Each original part uses consecutive1024-row tiles. A fixed1024-u16 link array plus at most512 eight-byte tile-group records forms stable repeated-class row lists without a tile sort/hash map. A class is merged only if its original scalar has at least two active digits; active testing stops after finding two. Identities/zeros are ignored. Every group stays within its tile/part.

All repeated groups are reduced together with the original complete group_affine kernel. Classification arrays are released before that reduction. Sparse sorted skip rows and (representative row,derived point) records survive the query. Windows pass unchanged contiguous key/scalar runs to the original borrowed batching loops, substituting one derived point at a representative and omitting its other rows. G2 flushes only at original component boundaries, transforms high buckets by the original Phi, then feeds low. Top windows use the original indexed reducer through a mapped point accessor. Original widths, partitions, weighting, digit/Phi formulas, field arithmetic, inverse kernels and complete exceptions remain.

An additional checked optional Reservation is acquired before any new heap allocation. Its conservative bound uses actual global duplicate count D, charges all new metadata/output vectors, per-tile group records and existing group-affine workspace, and doubles for possible old/new exact-reserve overlap. The original classifier remains separately charged until its arrays are released. Allocation/admission denial drops optional state and uses the already-classified raw route. No fixed architecture RAM ceiling, persistent key table, singleton point copy, duplicate solver plan, new pool or unsafe code is introduced. Compiler stack, process RSS and minimum RAM are not inferred from payload sizes.

Only diagnostic APIs select the new query implementation. First run focused native tests for source-classifier equivalence, span/mapped ownership, full weighted-generator oracles, denial/fallback, complete cancellation/doubling, ragged tile/part boundaries and512KiB custom-pool stacks. Field sources are unchanged and inherit current qualification. A/B2 fixtures are the prior immutable canonical point/scalar arrays. B2 reuses existing full-Arkworks oracle receipts. A requires a new complete-query oracle; the older ordinary-window bucket oracles omit its top and final weighting. No witness or proof solve is needed.

Before timing, freeze coherent control/candidate native libraries, actual caller executables, source/input/oracle/helper hashes, a full-query protocol and fixed case/block schedule. Complete query scope must include original global classification, overlay construction, all point formation, full ordinary/top fills, component/part merges, weighting, normalization, allocations/drops and dispatch/waits. Reset of exclusive B2 words is charged identically. Input load and independent reference work are excluded. Profile automatically after latency, with no owned builds/helpers/hashes/archives/other workload overlapping capture. No gain floor, favorable subset, exclusion, extension, layout sweep or unchanged reroll. A positive complete-query gate selects a separate all-eight+54 SDK/proof/resource/portable qualification; it is not adoption or the10× goal.
