Current msm.rs signs<SIGNED,C> loops over eight encoded indices to assemble one u8. Hypothesis: for a16-byte borrowed descriptor, two masked32-bit loads, one two-source permute and one vector sign-to-mask conversion can remove repeated scalar loads/shifts/ORs. First inspect actual native code: LLVM may already implement the scalar loop efficiently. Fewer static sites are not a cycle or full-proof gain. No speed prediction or2x claim.

Candidate helper stays in Rust intrinsics, changes only sign-mask construction. SIGNED=false returns0. Descriptor stride other than16uses the exact original scalar function. Borrowed native full-group slices contain at least8descriptors. Compute the first index address with addr_of!(batch[0].0), not an assumed tuple field offset. Mask0x1111selects defined u32 at byte offsets0/16/32/48; second load at+64selects64/80/96/112. No pointer or padding field is read. Two-source32-bit permute selects0/4/8/12/16/20/24/28into low8lanes; AVX512VL movepi32_mask collects high bits. Module/consumer requires native AVX512F/VL/DQ. This is distinct from adopted G2 signed-coordinate arithmetic; field formulas, sign meaning, queries, bucket representation and tuple layout stay unchanged.
