# DFT16 complete-caller experiment

**Rejected: the fixed Winograd16 caller is about 16% slower across the declared contexts, despite fewer IFMA instructions. Production is unchanged.** No real FFT/Euler or SDK integration is selected. This report completes the performance stage following the [mathematical and native qualification](../2026-11-08-winograd16-native176/README.md).

The independent offline reader agrees with the analyzer on all 2,430 commands, 2,340 caller processes, 48 contexts and 124 failed checks. All data/output/allocation/affinity and diagnostic-quality checks pass. The failed performance decision is retained without reruns, exclusions or selecting a favorable root, direction or worker count.

## Scope and controls

This measures two independent 16-point Fr transforms per caller iteration, using 64 changing fixtures per logical worker. It is a component measurement, **not single-proof latency or a complete FFT**. All eight primitive 16th roots, DIF and DIT, and 1/16/32 Rayon workers are included. DIF emits bit-reversed output; DIT retains both explicit bit reversals from the qualified candidate. Loads, shuffles, dummy lanes, corrections, constant products, stores and blackboxes are timed.

FROZEN is a newly built original-only diagnostic using the exact accepted source fragment and field library. OFF is the fresh original control; ON selects the qualified 13-product identity. FROZEN is not a historical full-FFT/SDK artifact. All three use the same accepted field1200 library, root/fixture owners, allocator, Rust1.98.1, -O, native CPU, fat LTO and one codegen unit. No C/ASM rewrite, key table, input-sized cache, retained solver plan or production pool is introduced.

The host is a Ryzen9 9950X with 16 physical/32 logical CPUs and AVX512IFMA. One worker is pinned to CPU2, 16 workers to CPUs0–15, and 32 to CPUs0–31, with individual start-handler affinity and 512KiB stacks. This is not an exclusive-host or cloud measurement. [Host inventory](artifacts/host.json).

Before any preflight, the full [protocol](artifacts/protocol.md), order, gates, actual caller decodes, independent goldens, analyzer and separate reader were frozen. There are 144 preflights, 2,160 latency processes in 15 rotated/reversed blocks, 18 grouped counter panels and 18 sampled profiles: **2,340 caller processes total, including the 36 diagnostics**. All recordings finish before the 90 offline decode/metadata/event/loss commands or other owned CPU work. Successful builds, tests, captures and decodes are not replayed for publication.

Each process primes three times, checking and resetting every fixture after each prime. Independent Arkworks matrices and repeated-transform powers generate 163,840 fixture digests over 5,242,880 final field values, covering every root/order/logical-worker/declared-round combination. Every process checks all 32 output fields of every fixture against these independent digests. Raw 512-bit inputs share only the deterministic byte generator; reductions and oracle arithmetic are independent. No proof or witness payload is generated by this experiment.

## Memory and interpretation

All2,340 caller processes report zero timed allocation requests, unchanged fixture capacity and complete oracle success. Fixture payload is81,920 bytes per logical worker, 2,621,440 bytes at32 workers. Candidate root-factor payload remains1,280 bytes per root, alongside the shared control/root state. Whole-process high-water RSS across this caller campaign is9,216KiB (9MiB). That includes driver/oracle/pool setup and is **not prover peak RSS, minimum RAM or a mobile/pressure/swap qualification**. Minor faults and CPU usage for every process remain in the full analysis and receipts.

The fixed kernel is closed. Fewer field products alone did not reduce total execution cost. No layout, compiler, worker-count, selected-root or DIT-transpose rescue is selected. The next research direction must identify a distinct reduction in complete MSM or FFT/Euler work, account for routing/correction/retention costs, and pass actual caller and verified full-SDK qualification before adoption.
