# Joint complex arithmetic: saved-profile postmortem

The [matched caller comparison](../2026-11-06-joint-pair52-capture176/README.md) rejects the joint complex implementation. This follow-up reuses all 18 saved profiles and nine existing consumer disassemblies. It adds no recording, decode, latency observation, proof or production change.

All **143,325 samples** reconcile with the reviewed campaign. Executable ELF64 LOAD segments and recorded executable MMAP2 file offsets normalize instruction addresses. The executable virtual-address/file-offset difference is checked rather than assuming they are identical. Every sample whose symbol identifies G1, G2 or the vector inverse maps to an exact decoded instruction boundary within that function. All three builds and all six profile contexts are retained. Other samples, principally scalar field inversion, remain separately reported. Input hashes cover the existing binary identities, reviewed profile streams, codegen and analysis source.

At 200 G2 points, the solo sample count rises from 5,432 to 12,410 with the same rounds and sampling period. Samples resolving to the three decoded core consumers rise from 5,021 to 11,977; scalar field-inverse samples are 408 and 429. At 32 workers the corresponding total counts are 7,704 and 13,986, with scalar field-inverse counts 444 and 472. At 352 points and 32 workers the totals are 13,271 and 24,129. These flat counts corroborate the much more expensive changed G2 path; they are not independent latency trials or exclusive cycle costs.

Grouped PMU instructions/cycles imply ON/OFF instructions-per-cycle ratios of approximately **0.516 solo**, **0.657 at 200 points/32 workers** and **0.654 at 352 points/32 workers**. The static G2 instruction count increases from 8,590 to 9,312; vector additions from 481 to 667, vector subtractions from 139 to 453, and signed shifts from 124 to 171. Saving IFMAs added substantial other work and enlarged live state. Neither static counts nor flat cycle samples prove how much of the loss comes from dependency depth, scheduling or stack traffic.

The highest single ON sample address at 200 points is `G2+0x7409`, a scalar read of `[rsp+0x88]`: 409 solo samples and 295 at 32 workers. Its neighboring instructions include overlapping vector stores and scalar loads. This is a useful inspection point, not proof of a store-forwarding stall: sampling skid and surrounding work prevent that conclusion. It accounts for only 3.30% and 2.11% of those profiles, so eliminating its attributed samples would not explain the full regression. The largest 256-byte ON window accounts for 3.37% solo and 3.06% at 32 workers; the loss is distributed across the function.

Instruction categories are descriptive. They classify IFMA first, then vector instructions with explicit RSP/RBP operands, then arithmetic, shifts, permutations and other instructions. Consequently a vector-stack category excludes IFMA instructions with stack operands. Categories count sampled instruction locations, not retired dynamic instructions, exclusive cycles, spill latency or removable wall time. Fixed 256-byte windows are address ranges rather than basic blocks. Normalized addresses do not remove sampling skid.

The implementation remains closed. Do not reopen its width, layout or attribute choices, rerun successful stages, select a favorable panel, or proceed to a slower SDK trial. The next candidate must reduce whole-path work or serial dependencies and justify its likely impact using existing production phase evidence, including ordinary field/Fr FFT behavior and memory costs. The accepted local 1×2 proof remains 7.928660 ms; no new comparison with Aeglos exists. The all-eight CPU10× goal remains active and unmet (0/8).

[Analysis](artifacts/analysis.json), [input pins](artifacts/pins.json) and [Rust analyzer](artifacts/postmortem.rs) preserve all panels and hot-address summaries. The analyzer checks exact address mapping, symbol/function agreement, instruction boundaries, disassembly counts and total/profile sample reconciliation. It runs once against existing evidence. This exploratory postmortem does not change the preregistered performance decision.
