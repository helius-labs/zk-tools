# Partial scalar-window sharing: bounded count screen

Declared before execution. Accepted175 production sources and timings remain unchanged. This is a count and algebra screen, not a field kernel, proof, latency or adoption experiment. The original goal remains verified single-proof CPU AVX latency at least 10x the supplied M5 CPU times on all eight shapes, with all CPU/Metal comparisons reported. No count result completes it.

Motivation: Hrabar, On the Performance of Pippenger's algorithm for Multi-Scalar Multiplication, Waterloo (2026-02-25), section 5.2, describes sharing point sums across matching nonzero scalar-window digits. https://uwspace.uwaterloo.ca/items/43cc12b9-cb03-42bd-a01c-4b0ed5e12403 . Independently implement a restricted disjoint-pair variant. This is not the thesis's recursive CRLC algorithm or its published benchmark configuration. No upstream code is copied. Earlier shared-point-window SIMD packing and whole-scalar grouping are distinct; their prior negative measurements remain closed.

Use the two immutable, independently checked G2 query fixtures (1x2, 2x2) from g2-queue-scan175. Validate fixture hashes, format, canonical fields, subgroup-independent fixture receipts, and production manifest before use. No new solver calls, SDK requests, independent proof exports or proof ledger entries. Never publish the fixture points, scalars or unblinded results. Group using the accepted zero-aware policy, stable first occurrence, 80/95 percent thresholds and current two-part exclusive G2 Phi2/Booth width12 route. Check copied grouping/split readers against their already qualified source functions. Report grouping decisions explicitly. For grouped inputs, structural point identity/cancellation is not determined by scalar metadata; it remains unmodeled. Input identity tokens are zero.

Within each production point-range half, partition consecutive rows into tiles of at most64. Compare all unordered original-row pairs across22 signed digit columns (11 per Phi component). Keep pairs sharing at least two equal nonzero digits. Sort by decreasing shared count then ascending left/right index. Greedily choose disjoint original-row pairs; no row is selected twice, no recursive auxiliary pairing, no negative pairing, no cross-tile or cross-part sharing. At most32 derived sums per full tile. For each pair, clear matching entries in both residual rows and feed one auxiliary row with those entries and point Pi+Pj. Count full-row equality separately from genuine partial equality. Do not silently label rediscovered whole duplicates as a new partial-window benefit.

For every rewrite, check every original coefficient exactly as signed integers: residual-left+common=original-left and residual-right+common=original-right in every column. Reconstruct both original Phi components in signed i128 and check their lambda combination against the original Fr scalar. Verify original/residual/auxiliary bucket sums with two independent deterministic Fr-token streams, and their weighted final sums against the original full scalar dot product. Every occupied magnitude bucket and indexed-top signed bin must retain the same structural occupancy. Count zero/identity input rows separately. Actual curve cancellation, exceptional arithmetic, inversion batching, borrowed queue dynamics, index-tree topology cost and latency are not modeled. The bucket-arrival reduction equals the generic noncancelling bucket-tree addition reduction only because occupied bins are preserved; charge one additional point sum per selected pair. This is an operation proxy, not saved measured CPU time.

Tests cover exact digit reconstruction at signed126-bit edges and deterministic values, zero/negative/full/partial matches, disjoint tie-breaking, odd/empty/tail tiles and partition boundaries, per-column integer conservation and both token oracles. Unchanged production field/core suites are inherited, not rerun for this standalone model. Compile/test/count through a source-pinned Rust xtask workflow. No performance capture, native curve kernel or production change.

Necessary opportunity gate: all algebra/bin/fixture/source checks pass, both shapes show a strictly positive generic net addition reduction after setup, and both shapes have at least one genuine partial pair. There is no arbitrary minimum percentage gain. If it passes, inspect search work and complete storage costs before choosing a native implementation; it does not automatically authorize a claimed speedup or adoption. If it fails, close this exact disjoint-pair scheme without a timing sweep. Report all results, including full-duplicate contributions, candidate comparisons, peak tile pair records, selected pairs and cap/tail behavior. Do not generalize rejection to all CRLC variants.

Memory: count helper allocations are analysis-only. A possible runtime layout needs4N residual-mask bytes plus12M pair-record bytes plus128M derived G2 point bytes, with N post-group rows and M selected pairs. These requested payloads exclude Vec headers/capacity rounding, tile scratch, normalization scratch, allocator overhead, stacks and existing query workspace. Original key points are borrowed, not copied. Per-key state is zero; derived sums are proof-local. A few KiB digit tile is not a complete-query memory bound. No production layout, admission, release, phone, huge-key, concurrent-proof, finite-pressure or swap qualification is claimed. Do not recode masked residuals into ordinary Booth scalars without an independent representation proof.

Publish source, design, pins, workflow receipts and aggregate counts only, alongside unchanged all-nine local/AWS and all-eight M5 CPU/Metal rows. Keep respectful configuration-specific comparisons. Commit and push the completed screen.
