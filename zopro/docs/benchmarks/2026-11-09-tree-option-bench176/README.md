# Tree-option owner complete-consumer comparison

The 32-worker balanced weighted consumer improves by 0.90% against the accepted reference and 2.62% against the fresh disabled control under the declared paired analysis. The complete gate fails nine of 89 checks: eight fresh-control calibrations and aggregate gain against the accepted reference. The primary gain is retained as a positive result; production is unchanged and this exact recipe is closed without adoption, an unchanged recapture or full-SDK follow-up.

This is a local component measurement. The accepted local full-proof 1x2 result was already **7.832708 ms**; this experiment provides no new proof timing. The historical 7.699867 ms figure used a different campaign and median of process medians. Neither figure is a matched measurement of this candidate. There is no new AWS or Aeglos comparison.

The candidate captures the tree-vector-inverse option once at entry to each nonempty grouped, indexed or weighted reduction and passes the boolean into scratch construction. It changes option ownership, leaving field arithmetic, queue geometry, Rayon task grain and allocation policy intact. It introduces no persistent lookup table, point copy, retained workspace, new pool or RAM cap. Changes to the option between calls remain visible. Native parsing, G1/G2, concurrency, generic compile and source qualification are inherited from the [parent experiment](../2026-11-09-tree-option-owner176/README.md), rather than rerun.

REF reuses the accepted 176-source core with only the common benchmark API appended. OFF and ON reuse the exact parent-qualified release cores; ON enables the private option-owner configuration. All callers use identical driver bytes and the original field, native O3, fat LTO, one codegen unit and allocator. All three actual links and source/library/binary identities were checked. One Rayon pool uses fixed CPU placement and default worker stacks on this local 16-core/32-thread machine. The generic parent build is a compile guard, not ARM execution.

Each timed wave includes the complete original weighted reduction, allocations and drops in the consumer, tree work, output collection and affine normalization. Loading, three primes and oracle checks are outside the timer. The balanced wave contains five 2048-bucket and fifteen 4096-bucket reducers, matching primary K/H bucket sizes; it excludes bucket filling, solver, FFT and proof assembly. Each other case has one reducer. Existing fixtures/oracles were reused byte-exact without regeneration: 94,720 distinct full-width scalar coefficients across 24 vectors, generated by a deterministic double-plus-fixed-point recurrence. These are neither independent random draws nor actual proving-key buckets. Every timed output is compared with its independent Arkworks oracle, and input hashes are checked for preservation. The historical label `fallback512` denotes an affected case here, with no unchanged-fallback claim or check.

Latency is the median of process arithmetic means of emitted integer nanosecond samples. Paired geometric ratios use corresponding blocks and 20,000 log-bootstrap resamples; medians need not divide to the paired estimate. The primary case has 31 blocks and each other case 15. Intervals assume exchangeable blocks and provide no familywise guarantee. All observations are retained without extension, exclusions or rerolls.

The primary OFF/REF calibration passes. Primary ON/OFF is 0.973829 [0.969124, 0.978627], with 30/31 wins; ON/REF is 0.991015 [0.986331, 0.995560], with 23/31 wins. Both gain and win checks pass. These support a small component gain against both controls, without establishing a full-proof gain.

The four-context native-32 aggregate is 0.950783 [0.946703, 0.954581] against OFF and 0.999988 [0.997014, 1.002906] against REF. It uses equal log weights and independent within-context resampling for 2048, 4096, 16384 and balanced20, not synchronized cross-case observations or the all-eight proof aggregate. The eight calibration failures concern the fresh OFF control versus original REF, mostly with slower OFF values; they are not evidence that ON regresses in those cases. This experiment does not establish a unique cause for the control difference. Possible compiler or constructor-layout effects require separate evidence and do not authorize a rescue of this closed recipe.

The RSS rule was fixed before clocks at ON maximum whole-process RSS <= 1.05 times control maximum plus 1 MiB. The allowance follows the existing complete-query convention for small-process granularity; it is neither an architectural cap nor a post-result exception. These component peaks include fixture and benchmark state and do not establish full-proof memory, minimum RAM or mobile behavior.
