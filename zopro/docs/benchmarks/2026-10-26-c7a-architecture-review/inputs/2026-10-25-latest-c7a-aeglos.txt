# Latest accepted Zopro and Aeglos on c7a.24xlarge

Fresh comparison of accepted Zopro with direct chain inversion and balanced GCD runs, the exact October 24 Euler Zopro executable, and pinned Aeglos 0290613 using its Sorted and Windowed engines. The dual-CIOS experiment was rejected before this run and is not included. Intervening allocator, solver/image-format and MSM changes are also present; this comparison does not isolate their individual contributions. No prover source is changed by this comparison.

Latest Zopro beats the faster tested Aeglos engine on 6 of nine circuits: 8x2, 12x2, 16x2, 24x2, merge-24x1, merge-54x1. Relative to the October 24 binary measured in this same run, latency changes range from -44.88% to +0.21%, selecting each build's fastest tested worker count. Aeglos default / Zopro peak-RSS ratios at their respective selected counts range from 3.61 to 7.33. The tables retain every circuit and worker configuration; best-count selection is descriptive.

The small 1→2 proof remains slower: 13.627 ms versus Aeglos Sorted's 7.966 ms. For 54→1, latest Zopro takes 129.985 ms versus 173.566 ms, with 1.75 versus 12.79 GiB peak RSS. The earlier Zopro executable takes 235.831 ms on this same server.

The server build uses 167 pinned accepted files and target-cpu=znver4. It passes 33 field and 104 core tests. Both Zopro versions use the exact October 24 SDK driver; the previous version keeps its original image files and latest Zopro uses its accepted images. The 16-worker AWS run is unpinned, unlike the separate local pinned-16 diagnostic. Both Aeglos modes use the same previously measured executable; the engine switch is recorded.

## Full request latency

Dedicated c7a.24xlarge, 96 physical cores, 30 GiB container. All nine circuits run at 16/32/64/96 workers with three rotating/reversing fresh-process repetitions. Each process excludes key loading and three priming requests, then measures 31 requests for 1x2 or 17 for other circuits. Timers include fresh assignment/witness solving, proof randomness, proving, verification and serialization. No owned CPU workload overlaps remote latency measurement. Per-prover retained runtime policies are recorded.

## Verification and cleanup

The exact-image local preflight passes 144 SDK requests with 36 distinct Gnark exports. AWS completes 8,016 measured plus 1,296 priming requests: 9,312 requests. One distinct measured export from each of 432 processes verifies remotely and again locally after retrieval; repeat verification is not counted as additional proofs. Combined: 9,456 SDK requests and 468 distinct independently verified exports. Public inputs, proof sizes, source/image/executable hashes and transport hashes are checked. AWS proof hashes are disjoint from the local preflight, preceding dual-CIOS timing and previous AWS exports.

Resource-event deltas: `{"throttled_usec": 162767}`. All per-process event and quota snapshots are preserved. Nonzero throttling or memory events are reported without an unchanged timing retry. Peak RSS and cgroup counters cover different scopes.

The owned instance is terminated, tagged EBS storage is absent and the private benchmark ECR tag is deleted. Cleanup is recorded. Accepted production source remains unchanged.
