# Scoped proof execution: C7a primary-circuit experiment

This experiment tests whether a private scoped proof graph improves primary-circuit CPU scaling. A prior local screen was negative: coarse jobs took9.300ms and overlap/fusion10.065/10.030ms, compared with9.080ms for the accepted version. This AWS run retains that negative observation and separately tests the96-physical-core hypothesis. No implementation is adopted by this diagnostic.

The result is negative. Accepted Zopro is13.386ms at32 workers, versus14.016ms coarse,14.731ms pipeline, and14.628ms fused. Aeglos Sorted is8.018ms at96 workers. At96 workers, fusion reduces warm CPU time by6.2% but increases latency by7.1%. None of these modes is adopted.

## Method

Dedicated c7a.24xlarge,96 physical cores,30GiB container. Primary1x2 only;16/32/64/96 workers, with16 unpinned. Three fixed rotated/reversed fresh-process blocks,31 measured verified SDK requests after three primes. Request timing includes assignment, fresh proof randomness, proof generation, verification and serialization. Key loading and preparation are excluded from warm timings and included in whole-process RSS. All Zopro versions use the same linked rusage wrapper and identical Euler image. No other owned build, profile or CPU benchmark overlaps the remote latency matrix.

Accepted uses the exact retained canonical128 znver4 libraries. Control is freshly compiled without the new cfg; compiled-off uses the new binary with runtime mode0. Coarse, pipeline and fused are modes1/2/3 of that same binary. Coarse introduces scoped window jobs and bounded scalar-gather task splitting; pipeline overlaps K with the product FFT and feeds H through the same K window states; fused also combines G2 bucket merging with bounded512-bucket weighted reductions. It creates no retained key tables. The baseline FFT and curve arithmetic are retained. Aeglos uses the previously pinned0290613 Sorted binary.

## Validation and limitations

The new target build passes33 field and112 core tests; the fresh control passes33 field and104 core tests. The new tests include independent generator oracles for complete A/K+H/G2 execution and panic propagation. The exact container preflight completes28 SDK requests and7 distinct Gnark-verified exports. AWS completes2,856 SDK requests, with84 distinct exports verified remotely and again locally after retrieval. Combined counts are2,884 SDK requests and91 distinct independently verified exports; repeated verification is counted once. Public inputs, randomized-proof identity, source, image, executable and transport hashes are checked.

The earlier local pressure diagnostic passed cold and warm88MiB high/192MiB maximum limits under both allocator policies, with no swap or OOM events. The optional path requires a conservative forecast for retained K states, per-worker scratch and graph metadata, plus admitted headroom in the active proof scope. After a warm pressure transition, subsequent proofs use the prior implementation. This is not a general memory-budget API or a physical-phone measurement. Portable backend, large circuits, production concurrency and full-suite adoption qualification remain outstanding.

The all-eight10× CPU goal remains unmet. This single-circuit diagnostic cannot establish a twofold general gain or reverse the negative local result. Resource event deltas are retained without an unchanged retry: `[]`.

Cleanup confirms the owned temporary instance terminated, no owned EBS remains, and the benchmark ECR tag is absent. Existing infrastructure is unchanged.
