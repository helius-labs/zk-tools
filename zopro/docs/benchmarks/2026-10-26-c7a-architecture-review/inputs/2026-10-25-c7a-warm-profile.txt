# Warm-loop CPU profiles on the fresh C7a comparison server

Separate diagnostic after the fixed latency matrix finished. Latest accepted Zopro and the same pinned Aeglos Sorted executable run on the same owned c7a.24xlarge at 32/96 workers for 1x2 and merge54. The predeclared trigger was the remaining primary scaling gap. These instrumented timings do not replace the unprofiled comparison.

The Zopro diagnostic wrapper links the exact server libraries used by the timing binary. The existing Aeglos driver already contains the same FIFO control hooks. Both enable counters after loading and three prime proofs, wait for acknowledgement, then disable before exporting. No source/library arithmetic changes, global CPU settings or kernel settings are made. All events follow only the launched process and inherited threads. The profile container adds PERFMON and permits perf syscalls through its own seccomp setting.

Three fixed counter repetitions use cycles, instructions, branches and branch misses in user mode; every event runs at least 99% of the measured interval. One separate 199 Hz cycle capture per case records no lost events. Flat reports use no percentage cutoff; raw compressed perf data and headers are retained. Software metrics come from getrusage around the warm loop. Counter attribution and summed CPU work do not establish critical-path wall time, DRAM bandwidth saturation or exact instruction causality.

At 96 workers, Zopro's primary uses 17.7 times as many voluntary context switches per proof as Aeglos, with 116.5 versus 24.8 ms of kernel CPU time summed across threads. At 32 workers, total CPU work is similar (317.4 versus 329.8 ms/proof), while Zopro has less average CPU occupancy. At 96 workers, Zopro uses 1.90 times Aeglos's summed CPU time. These observations support synchronization and work distribution as research priorities; they do not identify a proven fix or establish that RAM capacity is the limiting factor.

The leading Zopro primary/96 symbols are retained in analysis.json. Crossbeam epoch guard entry and epoch advancement are prominent. Earlier [empty-epoch collection](../2026-10-23-empty-epoch-collection-aws/README.md) and [fixed-time work search](../2026-10-23-timed-steal-aws/README.md) changes failed their latency gates; this new profile does not revive those rejected changes. The next scheduling experiment must change a distinct mechanism and pass latency plus memory checks.

For 54→1, Zopro uses less summed CPU time than Aeglos at both measured worker counts, despite greater system time and switching. The unprofiled parent comparison already establishes its latency and RAM advantage. The profile does not isolate which intervening accepted changes produced that improvement.
