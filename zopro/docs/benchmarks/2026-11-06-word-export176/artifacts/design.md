Hypothesis: canonical export need not subtract p in five radix52 digits. For mixed-R256 Fq only, pack the normalized value into four saturated u64 vectors first, subtract p with exact unsigned word borrows, select the canonical words, then execute the original transpose/store body byte-exact. Removing one digit and its masking/carry work may help actual callers. This is a small operation-removal hypothesis, not an established 2x path. Extra mask dependencies, earlier packing and register lifetimes can lose.

Bounds: every supported operation output is normalized and strictly below2p. Fq has 2p<2^255, so packing is lossless and one conditional subtraction suffices. Every modulus word is less than u64::MAX. Thus p[j]+incoming_borrow never overflows. For each word, d=x-(p[j]+borrow) mod2^64 and next_borrow=[x<p[j]+borrow]. Final borrow selects original x; otherwise d. This is not claimed correct at inclusive2p (which would require a second subtraction), arbitrary unnormalized inputs, other moduli, Fr or uniform R260.
