# Tagged scalar ownership audit

The sole production call to `centered::exclusive` is inside the canonical-wire fused branch in `Key::solve_canonical_wires`. `sa_vec` is freshly collected from canonical witness words, has its own allocation, and is not shared with `sb_vec` or `w`. Its mutable borrow is confined to the A closure. The other joined closures read K from `w`, B from `sb_vec`, and H from the product vector. The fused branch returns after serializing point results, with no subsequent scalar reader. Rust accepts these ordinary borrows without new unsafe code.

OFF, unsupported original length or unavailable native borrowed support returns through the original `msm_canonical` before encoding. The existing optional grouping decision also runs before encoding. If it succeeds, the fresh grouped point sums and owned `groups.values` feed `run`; a grouped length outside the native range returns through the original raw path without tagging. If grouping declines, only the caller-owned A words are tagged. Group metadata and its reservation stay alive through the same reduction consumers as before.

After encoding, the only scalar reader is `borrowed_pending::msm_centered`, specialized with `CENTER=true`. Both of its consumers clear bit255: the centered digit reader used by `Window::feed` and the centered final-window counter/order construction. No tagged value enters scalar grouping, Fr arithmetic, a G2 split, the K/H path or the original positive-only top reducer. The final-window point order uses the existing u32 storage; bit31 marks a negative point and is masked before indexing. All such calls have fewer than65,536 bases.

The sign tag uses bit255, above the highest possible canonical Fr bit253. Centered magnitude is at most floor(r/2), at most253 bits. Top bucket sizing uses that magnitude bound and leaves the native signed-window count unchanged, including carry-only final windows. Identity points are skipped before insertion, and signed indexed point sums retain the existing complete reduction handling.

The encoder changes values within the existing four-word allocation. It adds no scalar Vec, sign bitmap, key point transform or persistent table. Existing Rayon scheduling can still allocate task metadata; this is not an assertion of zero process allocation. Signed top reduction reuses the old tiled points/task/scratch structures and has no larger bucket bound. This audit is a source/storage argument, not whole-process RSS, allocator-failure, pressure, concurrent, phone or TEE qualification.
