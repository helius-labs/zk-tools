# Warm CPU work on compact and spread C7a placements

The archived C7a catalog showed Zopro using roughly three times as many CPU-ms per proof on its 96-core loss cases as it used at 32 cores. The new experiment measures how much of that growth comes with more retired instructions, and how much comes with more cycles per instruction. It pairs the ordinary Zopro release and prepared Aeglos on 1×16 and 5×16. On each engine it compares 32 physical cores packed into four L3 domains, 32 across twelve domains, and the full 96. Linux topology and affinity are recorded for each launch. [Historical widths](../2026-11-19-c7a-width672/README.md) · [Placement protocol](../2026-11-19-c7a-placement674/README.md)

Each of six blocks has a plain process and a separate counter process for every engine, shape and placement. Their order alternates by block. Each process warms three requests, times fifteen sequential requests and exports one proof for independent verification. The SDK enables two grouped user-mode events after warmup and disables them before export. The launcher requires positive counts for both events and at least 98% counter running time. It emits the totals and percentages in the command's standard error. The original verifier checks the proof and public input with the pinned key.

Compare plain elapsed time, CPU-ms per proof and peak RSS across widths. Divide event totals by fifteen for per-proof work. At a given shape and width, also compare the instrumented elapsed time against its paired plain process to quantify measurement overhead. More instructions per proof would direct attention to extra operations and worker coordination. Similar instruction totals with more cycles per instruction would direct attention to stalls, including synchronization and data access. Distinguishing individual causes requires phase profiles. Aeglos exposes per-request MSM times in both arms.

Eight Ryzen smoke exports verified across the two engines and two shapes. All four instrumented processes reported both events with 100% running time. A separate native test/build was active during this functional check. Its timing is unsuitable for estimating speedups. C7a results await a fresh AWS session.

To run on the C7a, overlay the local `c7a-placement674/addon` and `c7a-warm-counters682/addon` directories from the performance workspace onto the existing `/opt/zopro-wide663` pilot. From that directory run `bin/xtask workflow counter-workflow.json counter-results`. The supplement adds 144 timed processes and their verifiers. On hosts with restricted perf access the launcher uses the benchmark account's existing noninteractive sudo access for perf, and starts the measured prover as the original user.
