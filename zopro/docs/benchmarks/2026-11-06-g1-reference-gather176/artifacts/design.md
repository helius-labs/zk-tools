# G1 reference gathers: code-generation screen

Hypothesis: the current G1 affine stream's forward loops materialize two arrays of eight whole affine points before packing X/Y. Gathering references instead may remove temporary coordinate copies and stack traffic. LLVM may already remove those copies; source appearance alone is not evidence of work removed. This is a small candidate, not a claimed twofold improvement.

Use the exact176-file accepted manifest. Keep original stream byte-exact and clone it into a private child with ONLY the two forward A-array and two forward B-array gather expressions changed to references. Borrow checking preserves immutable source/destination reads during forward processing. Original arithmetic, signs, invert/tail paths, reverse loop, scratch layout, store modes, batches and resource policies remain. No field/key/solver/pool change, LUT, input-sized buffer, unsafe addition or runtime production dispatch is introduced. Original and changed kernels coexist in one diagnostic executable, with the same fixture and selector outside each call. Existing caller helpers are diagnostic-only appendices; all original bytes must recover.

Audit: earlier compact-G1 scratch, late-G1 coordinates, raw scratch, bucket52 and unit-prefix experiments change record representations, coordinate rereading, arithmetic or peeled boundaries. They remain closed. This trial changes the temporary gather operand types alone; it does not claim a new MSM algorithm. Current accepted SDK profile has20.20%flat samples in signed borrowed G1 stream, including its inlined payload, not a removable-time bound.

First execute meaningful correctness tests for signed/owned inputs, tails, original scratch modes and 1/4/16/32-worker small stacks, then optimized native/fatLTO/oneCGU linking. Field source is exact; existing field qualification is inherited, not rerun. Static comparison inspects actual linked original/changed functions, IFMA count, frame layout, stack operands, source loads and instruction identities. Function merging or identical normalized emitted code closes this candidate without timing. If changed, inspect which concrete operations disappeared before declaring a matched caller protocol; code-size or static-count change alone does not qualify a speed gain. No unchanged previous measurement is rerun, no performance gate or full-proof gain is claimed at this stage.
