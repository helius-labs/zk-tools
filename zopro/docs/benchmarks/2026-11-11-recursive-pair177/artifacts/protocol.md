# Recursive proof-local pair reuse: scalar-only screen

Use the two retained, independently curve-qualified B2 fixtures from the global
window-pair study. Check their hashes. Filter identity/zero rows and separate exact
full-scalar classes as that study does. This is a favorable opportunity model;
production grouping admission is not replayed, and primary currently declines it.

Extend the earlier deterministic disjoint-pair construction recursively. Within
each generation visit the 231 column pairs in lexicographic order, group unused
rows by their simultaneous-sign-canonical two-digit key, and pair consecutive node
indices. Consume every shared nonzero column with that orientation, create one
sum/difference node carrying those digits, and retain both residual rows. Each
existing node participates at most once per generation. Newly created nodes enter
the next generation. Continue until a generation forms no pairs. Do not change
ordering or rerun with different parameters after observing results.

Charge one point formation for each generated node and each full-scalar group
edge. Count all residual/new-node arrivals. Report generation counts, incremental
gain, initial/final arrivals, formation cost, recursive depth and storage payload.
Each formation removes at least two arrivals, so termination and node growth are
bounded by initial arrivals / 2. No claim of optimality or whole-proof speedup.

Verify the entire final DAG by propagating exact signed coefficient vectors back
to original rows, column by column. Each recovered coefficient must equal its
original signed digit. This is stronger than random linear checks. Use exhaustive
small inputs against a separately expressed naive grouping oracle, and a crafted
recursive case. Reuse qualified Phi2/Booth helpers, checking integer component and
Fr scalar reconstruction for all fixture values. No point/proof arithmetic test.

Preserve first-generation counts against the earlier study as a regression anchor.
Use the final column-class census to certify no eligible same-sign/reversed pair
remains, including zero residual rows. Preserve aggregate outputs only, never
private digits/scalars/DAG or proof inputs in repository artifacts.

The decision is whether recursive reuse exposes substantially more opportunity
than the recorded one-generation result, and whether further curve-cost analysis
is warranted. No minimum gain adoption rule: this is research prioritization.
Arrival counts exclude first writes, partition/component merges, weighted trees,
point exceptions/cancellation, inversion and SIMD occupancy, classification cost,
packing, and all runtime memory. Native integration requires those costs and a
short verified full-proof screen. No native candidate is adopted by this screen.

Run through the existing Rust xtask workflow. Record command durations separately
from preparation/analysis. Keep accepted source/SDK and the 53,917-proof ledger
unchanged. No publication or push is authorized.
