# Unimplemented SIMD follow-up

The scalar integer identities need native implementation and oracle qualification before a performance comparison. This file is a design lead, not a claim that these helpers exist or are fast.

For CRT output, there are18 fixed Fr coefficients:17 (M_i modr), plus (-M modr) for the correction k. Their numerical Montgomery words a_i are canonical belowr. Every factor t_i<2^31; the correction k<=17 also satisfies that bound. Precompute mu_i=floor(a_i*2^31/r), with mu_i<2^31. Then q_i=floor(t_i*mu_i/2^31) has product below2^62 and leaves0<=a_i*t_i-q_i*r<2r. Instead of reducing18 separate field products, accumulate18 radix52 integer products, subtract (sum q_i)*r once, and normalize. The exact residual is below36r<2^260.

With B=2^52 and r4=floor(r/B^4), let h=floor(B/(r4+1)). Estimate the remaining quotient by floor(top_limb*h/B). Since r4 is between2^45 and2^46 and the residual is below36r, this estimate is below the true quotient and differs by at most1: a conservative real error bound is36*(r4+1)/B+37/r4<1. After subtracting its modulus multiple, one canonical subtraction is enough. Signed coefficient carries and every accumulator bound must be independently checked, not assumed from the final integer bound.

An eight-lane scalar source recipe would use18*10 IFMA product halves,10 for the shared quotient/modulus product,1 top-limb estimate, and10 for the final small quotient/modulus product:201 IFMA sites before normalization/linear/packing work. This is a source recipe count, not linked instructions, execution count or a speed prediction. A general Fr dot product is not an appropriate optimistic performance comparator. Added loads, transpose, carries, register pressure, scalar tails and output conversion all remain charged.

The residue projection can process eight coefficients in64-bit lanes, transpose four Montgomery words once, then apply each prime's eight fixed32-bit chunk weights. All products fit64bits and total low-word overflow is intentional. Reciprocal products and one final correction use only integer instructions.
