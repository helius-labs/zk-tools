# Signed component alias screen

Hypothesis: equal signed-magnitude G2 Phi2 components can share point sums even when their full scalars differ. This removes repeated bucket arrivals over multiple windows without any persistent point table. The motivating upstream code is AztecProtocol/aztec-packages commit 3c7386eb7bbddec89bb6548982583eb65bb563bc, pippenger_rewrite_review_map.md, which explicitly allows equal working halves to group after GLV. No upstream timing is transferred, and no upstream runtime is copied.

Before reading results, fix two retained B2SCAN01 inputs (1x2 and 2x2), the current Phi2 split, 12-bit Booth recoding and two original point-range partitions. Within each partition, first contract equal full scalars modulo sign. This deliberately optimistic comparison removes ordinary full-scalar reuse from the alleged new opportunity, even when production would decline its grouping policy. Then group each component by nonzero magnitude, absorbing signs into its point sum. Group only classes occurring at least twice with at least two nonzero Booth windows. Charge m-1 additional generic point additions to form a component sum; removing m-1 identical arrivals at w windows saves (m-1)*w, hence net (m-1)*(w-1). Unit/one-window classes stay untouched. Zero and input identity rows are excluded. No cross-part or cross-component grouping is allowed.

Necessary novelty gate: primary extra net generic additions saved after signed full-scalar contraction must be strictly positive. This is a necessary operation screen, not permission to adopt, a timing prediction, or a claim that the optimistic contraction is the accepted implementation. If zero, close this particular additional-component-reuse lead before native implementation. If positive, inspect its complete operation mix, setup, prefix/reduction geometry, actual caller and live-workspace/admission costs before proceeding. Do not ignore positive estimates merely for being small, or turn a count pass into a latency gain.

Validate exact full-scalar reconstruction with the accepted Fr arithmetic and current lambda for every retained row. Validate component grouping and every weighted bucket via two small-prime additive token groups; these are not elliptic-curve or proof oracles. Tests independently compare grouping to explicit per-row bucket insertion and cover signs, zeros, identities, multiwindow classes and partial parts. The primary operation census 633620 generic pairs is an inherited context only, not the denominator of a qualified speedup.

Memory is not qualified by this screen. A future implementation must keep original point lifetimes, high-to-phi-to-low semantics, all ordinary bucket widths and partitions, and resource fallback. Sorted/hash metadata, new component-derived points, their reduction scratch and existing key/prover workspace all count. No arbitrary cap, extra pool, giant LUT, copied proving key or duplicate retained solver plan is permitted.

Run one four-step Rust/xtask workflow: compile tests, run new tests, compile count helper, run count helper. No CPU timing or profile is needed for a structural alias question. Pin source, inputs, toolchain and libraries before the workflow; retain failures and repair only failed work. No new SDK requests or Gnark proofs; canonical ledger stays 29953.
