# Fixed complete-filler screen

No captures have been run when this protocol is written. Original control is
compiled without zopro_deferred_equality. OFF and ON use the same candidate
executable, with the selector outside the field kernel. Both wrappers use
accepted native flags and final opt-level=3, fat LTO, one codegen unit.

Two real raw pre-group G1 A fixtures (1x2 N=21006, 2x2 N=36637), original pinned
g1-columns176 ACOLMSM1 inputs and ACOLREF1 independent Arkworks bucket oracles.
No fresh solve, input generation, oracle run, SDK proof or ledger advance.
Each pass fills all 21 ordinary width-12 windows, including fresh Window
allocation, admission, queues, checked inverse/fallback, normalization and
destruction. Original top-window special handling, weighted sums and proofs
are excluded. No digit matrix or other new input-sized buffer is used. Native
Option/tag/codegen/stack differences are not claimed memory neutral.

Six contexts: both shapes times workers 1/16/32. Whole process affinity CPU2
solo, 0-15 physical, 0-31 logical; Rayon 512KiB stacks, migration within mask.
18 one-pass preflights, then 15 fixed rotated/reversed blocks x 6 contexts x
3 arms x 20 passes. Every caller has three oracle-checked prime passes and
one checked post pass. No exclusions, extensions, successful reruns or gain
floor. All latency precedes 6 grouped PMU and 6 fixed-period cycles:u profiles
at primary16/32, 200 passes each. FIFO gating excludes primes. 30 read-only
ownership/decode/events/loss commands follow. Total 330 commands/300 callers,
9018 complete passes including primes/post, 51609600 prime/post bucket checks.

Ranks4..12 of15 paired ratios give nominal96.484375% marginal intervals under
independent exchangeable blocks, without familywise guarantees. Every OFF /
original calibration interval must fit [1/1.03,1.03]. Every ON/original and
ON/OFF context must have upper<=1.03. At 32 workers both equal-log two-shape
aggregates must have upper<1 and >=10 wins. No adoption from solo subsets.
Profile qualification: zero LOST, ownership/CPU/mmap/task checks, >=400 samples
per profile and unknown<=5%; counts below1000 must be called thin. PMUs require
>=99.9% running. RSS/faults from inherited counters are diagnostic due previous
undercounts, not precise peaks, minimum RAM or a latency-cost attribution.

No owned compilation, analyzer, hashing, archive creation or second workload
overlaps latency/profiles. Production remains unchanged whichever result.
A successful caller screen still requires actual routed full SDK proof,
independent Gnark verification, all-eight CPU/Metal comparisons, resources
and compatibility before any adoption.
