# Reproduce as a new experiment

Do not overwrite or rerun the completed capture. Create a new output root and declare any new hypothesis before using it.

1. Verify `SHA256SUMS` from the report directory. `receipts.json.gz` is a deterministic gzip-compressed JSON object with a `members` array. Each member has `path`, `utf8`, `bytes` and `sha256`. Decode `utf8` exactly, including final whitespace; verify its UTF-8 byte length and SHA256 before writing a relative path. Only regular source/receipt streams are included, not executables or raw perf.data.
2. Use the accepted source manifest linked in the report to recover the original production source176. Preserve binary fixture bytes. Original accepted SDK/library hashes are identities, not a claim that a fresh compilation produces the same binaries. This study deliberately compares the archived original accepted libraries; a fresh rebuild is a new control requiring its own calibration.
3. This is a synthetic component study: it does not require a proving key or private witnesses. `base.rs`, `direct.rs` and `native.rs` are the complete parent/scalar/native module tree. `qualify.rs` is the full-size independent polynomial driver. `bench.rs` is the original/fresh shared operator driver; `perf.rs` is its FIFO/rusage support. The pinned `tfhe-ntt 0.7.1`, `num-bigint`, `num-traits`, Rayon and field/core dependencies are listed in `libraries.json` and the source pins. Parent Cargo files/upstream/license metadata are included.
4. Read `plan.json` and the `runs/*/command.json` archive members for actual correctness-build/test arguments. Use explicit installed Rust 1.98.1 paths. Required native flags are `-O -C target-cpu=native -C lto=fat -C codegen-units=1`; checked mode additionally enables debug assertions and overflow checks. Select a coherent field/core/Rayon dependency graph. Use LTO-capable serde_json for the optimized drivers. Original accepted-library paths must be supplied locally to reproduce this particular control; do not silently substitute fresh same-source libraries.
5. `build-plan.json` declares the two driver links. The original-only driver excludes the native module. The fresh driver defines `crt_native` and implements both OFF/ON. Original accepted sha2/libc dependencies and every explicit compiler argv are in receipts. Adjust only paths into the new root and corresponding new pins; preserve the old evidence.
6. `capture-design-final.md`, `capture-plan.json`, `cases.json`, `jobs.json`, and `campaign.rs` fully describe ordering, fixtures, rounds, affinity, environment, controls and gates. Drivers take `ARM DOMAIN WORKERS ROUNDS latency|profile`. Use FIFO-gated `perf` through the existing Rust/xtask workflow and keep diagnostics after all latency. Do not run other owned CPU work concurrently. The final declaration uses 4097 calls for each profile; the original 501-call declaration is retained as history.
7. The independent `review.rs` intentionally uses absolute historical paths and refuses to overwrite a successful `review.json`. Adapt paths/output names for a new review. It imports serde_json/sha2 only and does not include campaign/statistic parser code. Compile helper tools without LTO when using non-LTO helper dependencies. The initial reviewer failure and corrected normalization of empty protocol defaults are preserved; no runtime capture was repeated.

For this completed run, all raw timing arrays, rusage/preparation values, full decoded profiles/metadata/event/loss outputs, commands, exits and stream hashes are in the receipt archive. `analysis.json` and `review.json` contain derived results. Source hashes and original raw perf.data paths remain pinned, but raw perf.data and binaries are intentionally not published. The full-proof baseline and proof-ledger hash are inherited, not component-derived proof qualifications.
