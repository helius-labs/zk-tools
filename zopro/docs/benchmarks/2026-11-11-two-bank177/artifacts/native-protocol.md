# Native two-bank feasibility qualification

Build an isolated current-source snapshot with a private diagnostic API. Do not
select the candidate in any production prover route. Original one-bank Window
remains exact; an appended adapter drives it with explicit signed bucket indices.
A separate child implements two banks, one shared original affine batch, original
sparse projective accumulators, and a single full final bank-merge batch.

Exception handling must map either bank's equal-point spill to its logical bucket;
inverse points clear only their selected affine accumulator. Final projective
normalization merges into bank0 before bank1. Keep the key borrowed and immutable.
The full merge can grow prefix scratch beyond the original streaming capacity;
count-screen storage is not a total native memory forecast. Resource admission,
production dispatch and performance are deferred until correctness is established.

The driver uses independent Arkworks public points/field elements. Check both old
and new complete bucket outputs against Arkworks projective accumulation, including
identity/repeated/opposite inputs, positive/negative operands, clustered and spread
destinations, empty cases, both-busy queues, spills and final merges. Check input
bytes unchanged. Sizes1/63/65/2048/4096 and capacities8/200/352; four input patterns,
4097arrivals each. Run one additional pattern per worker in pools1/4/16/32 using
512KiB stacks; four OS callers share one8worker pool. This is native SIMD state
qualification, not full-query/SDK proof, portable device or memory qualification.

Freeze source, build and run plans before invoking them. No timings used to select
performance. Any correctness failure stops native progression and is preserved.
